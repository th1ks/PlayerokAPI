# Как участвовать в разработке

## Ветки

| Ветка       | Назначение                                        |
|-------------|---------------------------------------------------|
| `main`      | Релизное состояние. Тегируется, уезжает на PyPI.  |
| `develop`   | Интеграционная. Сюда вливаются все фичи.          |
| `feat/*`    | Новая функциональность.                           |
| `fix/*`     | Исправления.                                      |
| `docs/*`    | Документация.                                     |
| `chore/*`   | Инфраструктура, CI, зависимости.                  |

Пулл-реквесты идут в `develop`. В `main` вливается только `develop` перед релизом.

## Коммиты

[Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/):

```
feat(chats): добавить итератор по сообщениям
fix(transport): не терять cookie при редиректе
docs(api-map): уточнить маршруты BFF
chore(ci): поднять версию ruff
```

## Перед пулл-реквестом

```bash
pip install -e ".[dev]"
ruff check .
ruff format --check .
mypy PlayerokAPI
pytest
```

## Правила для кода

- Python 3.10+, весь публичный код типизирован.
- Никаких синхронных HTTP-вызовов — только `httpx.AsyncClient`.
- Зависимости добавляются с обоснованием: библиотека позиционируется как лёгкая,
  ядро держится на `httpx` и `websockets`.
- Каждый модуль в `methods/` отвечает за один домен и не лезет в чужие транспорты
  напрямую — только через `Account`.
- Сетевые тесты пишутся на `respx`, живые запросы к Playerok в CI не ходят.

## Новые ручки API

Если нашли маршрут, которого нет в [`docs/api-map.md`](docs/api-map.md):

1. Опишите его в карте API — метод, путь, бэкенд, какие параметры.
2. Укажите, как он был найден (чанк фронтенда, вкладка Network, ответ сервера).
3. Только потом добавляйте метод в библиотеку.
